# DESIGN_SYSTEM.md

## Purpose
This document defines the visual and interaction language for the product, including how the Figma design should be translated into implementation.

## Core Principles
- Keep the experience simple and trustworthy
- Show clear progress and feedback during downloads
- Make actions obvious and low-friction
- Support both beginner and advanced users

## Visual Tokens
- Primary color: blue or brand accent for actions and highlights
- Secondary color: neutral gray for supporting UI
- Success color: green for completed operations
- Warning color: amber for retries or caution states
- Error color: red for failed downloads

## Typography
- Use a clean sans-serif font family
- Headings should be concise and scannable
- Use clear hierarchy for primary actions and secondary information

## Spacing and Layout
- Use consistent spacing scale for cards, panels, and form sections
- Keep dense information grouped into clearly separated sections
- Preserve generous whitespace in empty or secondary states

## Component Guidelines
- Primary button: used for main actions like Download
- Secondary button: used for optional actions like Settings
- Progress state: clearly display current task and completion percentage
- Empty state: explain what to do next when no items are present

## Figma Handoff Notes
- Map each Figma frame to a real implementation state or screen
- Record text content, spacing, color usage, and component variants
- Keep any interaction states such as loading, success, and error visible in the design spec
